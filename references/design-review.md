# 页面验收

检查生成的真实页面，与本次参考并排或依次对照；不能只检查源代码或根据截图文件存在就宣布通过。

## 内容与视觉

- 首屏能识别人物及其方向，图片有明确用途，实际人物照片没有被遗漏或误换。
- 氛围图下方没有自动生成的素材分类、制作说明或非必要来源链接，也没有遗留空白占位；来源已保存在素材清单，必要署名和有意义的作品说明按需要保留。
- 重点项目说明问题、本人动作、结果/当前状态。数字范围、贡献边界与源资料一致；没有用装饰图冒充作品。
- 与选定参考比较图片占比、标题尺度、图文关系、主色和栏目变化。列出采用与调整的地方，不以“高级”“有设计感”代替具体判断。
- 检查真实长标题、短资料、无图、有图的情况；无内容栏目不显示，重点不被大量装饰抢走。
- 桌面、手机检查溢出、图片裁切、正文大小、文字对比度、留白和图片加载。建议检查 1440、390 及 320px 宽度；工具不能调整宽度时明确记录实际视口，不伪称完成手机测试。

## 交互

- 导航和页内定位，项目详情及返回、下载、图片原图链接均实际点击。
- 有人像时测试悬浮预览、点击完整图、手机触发、关闭按钮、Escape 及关闭后焦点回到头像。
- 仅键盘也能操作；没有悬浮的触屏环境不能失去入口。
- 页面尊重减少动态效果设置。检查功能即使没有动画也成立。

将通过浏览器实际观察的结果写入 `review/visual-checks.json`：

```json
{
  "status": "partial",
  "checks": [{"name": "桌面首页", "result": "passed", "viewport": [1440, 900]}],
  "screenshots": ["desktop.png"],
  "limitations": ["示例：尚未完成手机交互检查"]
}
```

修复真实发现的问题后再重查对应项；保留实际截图和结果。所有约定检查完成才改成 `passed`。发布需要用户指令，本地验证完成不会自动触发发布。
