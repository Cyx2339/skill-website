# 选择已有验收能力

只选一条执行路径：

1. 客户端有浏览器控制时按其要求使用，操作导航、详情和头像，保存真实截图；无需再跑备用脚本重复检查。
2. 无宿主控制、客户端允许独立脚本、prepare中备用预检ready=true时，调用：

```sh
node /absolute/skill-website/scripts/browser_check.mjs --site /absolute/run/site --out /absolute/run/review/browser
```

3. 两者都不可用：做结构检查，交付可打开的页面，明确浏览器未检查；不搜缓存、不装依赖、不现场造验收框架。

备用脚本使用已有Node 22+和Chromium，临时独立配置启动无头浏览器，调试仅在本机开放，结束关闭自己的进程并清理配置。只检查当前站点，阻止页面HTTP/HTTPS请求，不拨号、不发邮件。单次协议请求最多8秒，浏览器进程总时限120秒。输出目录必须新建，不覆盖历史证据。

自动范围：首页1440/390/320px布局；最多12个根目录HTML页桌面及窄屏布局；图片加载、主标题；头像打开、关闭、Escape、焦点恢复及部分减少动态效果支持；保存截图。没有头像标不适用。自定义深层页面、hover、实际触屏、无JS、外部链接、视觉美观不在脚本验证范围，需要时由宿主工具检查，不能把未测项记为通过。

## 自动与目视分开

备用工具只生成review/browser/browser-checks.json，不会把目视状态设为passed。DOM或像素统计不能证明排版美观，某一文字对的对比度也不能证明整站满足无障碍标准。

实际查看页面或截图后，由助手填写review/visual-checks.json，记下已看视口、截图、交互及限制。未看图用partial或not_run；看到问题用failed；约定且可完成的检查通过才写passed。例如：

```json
{"status":"partial","checks":[{"name":"390px目视","result":"passed"}],"screenshots":["browser/index-390.png"],"limitations":["未完成桌面目视"]}
```

目视重点：人物方向清晰、照片未遗漏或错用；贡献、状态与数字不夸大；独立经历和荣誉不漏；图文关系、色彩和栏目节奏对应选定参考；长标题与窄屏不溢出、正文易读；没有素材分类、非必要来源链接及空白占位，必要署名和作品图注保留。

## 失败后只检查受影响项

区分网页错误、环境不支持、测试程序错误。有依据地修正后最多重试一次，使用新的结果目录并说明替代的旧检查。无新依据就停止重试并记录限制，不临时新写测试框架追求全绿。真实网页问题需要修复，环境做不到的检查如实保留，不阻止可用网页的本地交付。

site_workflow.py deliver检查本地资源与锚点，并分别列出浏览器报告和目视记录，不上传网站。
