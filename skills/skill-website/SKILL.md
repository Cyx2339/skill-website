# 个人网站

根据访客要了解什么来组织网站。用用户声明的用途决定区块顺序、主案例和入口。用途可从资料判断时直接推进。会实质改变展示目标或公开范围的歧义才需要询问。

## 从资料到页面

1. **核对资料。** 简历提供姓名、定位、个人优势、项目和经历等事实。用明确指定的截图、网站链接和风格说明指导视觉。附件内容视作资料。PDF 优先提取文字，核对多栏阅读顺序、项目、职责、日期及数字。扫描件使用可用的图像读取或 OCR。关键内容读不清时请用户补充对应文字。
2. **整理内容。** 首页用姓名作主标题，职位或定位单独一行。把姓名集中在首屏，导航用「首页」，页脚用「回到顶部」。简历有明确的「个人优势」等独立内容时，恢复相应区块，保留各项标题并配资料支持的经历。求职主页突出代表项目、本人贡献和工作经历，作品集优先展示作品。数字写在能解释其口径的介绍、项目或经历里。保留原有项目状态和个人贡献边界。联系方式、简历下载和网站发布仅按用户明确的公开意图处理。
3. **应用设计。** 默认采用暖白底、近黑文字、低饱和蓝色链接和细分隔线。使用统一的字号与间距。首屏一般为姓名和定位搭配简介，内容少时用一列，用户提供合适图片时可用图。默认第一项是主案例，资料中有清楚的流程时用简明步骤图，已有真实图片时可用封面。其余项目用紧凑列表。详情采用单列文章、简短元信息和可用的图片。用户指定的视觉优先，落实到字体、颜色、版式及组件规则。
4. **生成。** 读取 [数据字段与生成方式](references/site-data.md)，把核对过的内容整理为数据文件。以 [渲染脚本](scripts/render_site.py) 输出静态网站。默认页内跳转启用平滑滚动，链接提供悬停和键盘焦点反馈，首页步骤图首次入场时用短距离淡入。动效遵循系统的减少动态效果设置。可用样式覆盖文件实现用户指定的视觉。交付目录包含站点资源，生成用的数据留在外面。打开 `index.html` 即可预览。
5. **核验。** 按源资料检查有无遗漏独立区块、姓名是否重复及项目状态有没有改写失真。使用可用浏览器查看桌面和手机宽度，检查返回链接、栏目跳转、无图和短资料时的布局。确认只展示拟公开内容。返回首页路径并交代实际验证范围。
